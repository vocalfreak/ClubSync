# ClubSync Glossary

Terms as this project uses them.

- **Ingestion run / `IngestionRun`** — one pass of the `clubsync:ingest` rake task over the account list (every 2 days). The `ingestion_runs` table row is the single source of truth for what a run produced and what the Discord summary reports.
- **`is_event`** — nullable boolean column on `posts`, `nil` until a post reaches `extracted`, then derived once from the post's stored `category` via the `Categories` constant: the extraction LLM picks the category; the category→`is_event` mapping is pure code, no threshold. Independent of whether an `events` row exists (that table holds structured field data for confirmed events).
- **Grace time** — healthchecks.io's "how late can the ping be" window past the 2-day period before the check is considered failed and `#clubsync-alerts` fires. Crashes don't wait it out — the app pings `/fail` immediately.
- **Hermetic notifier** — a reporting hook (`DiscordNotifier`, `HealthPing`) that rescues its own errors, logs them, and never raises. Control-plane failures never change run status and never suppress another notifier.
- **Dead-man's switch** — the healthchecks.io check acting as the external backstop for the app never getting to self-report (box down, OOM-kill, cron never fired).
- **Terminal stage / `deduped`** — the last pipeline stage (`scraped → media_processed → extracted → deduped`). A post that has reached `deduped` is "fully processed": post-loading skips it entirely on later runs and no stage re-runs for it. `extracted` is the last stage in the code until dedup exists: the enum keeps `scraped: 0, media_processed: 1, deduped: 2, extracted: 3`, so `extracted?` is already the highest stage and `PostLoader`'s current skip guard is correct for now.
- **Canonical event** — the `events` row in an event group that the public site's card shows, chosen from the group by field completeness and confidence. Not a merge target: a post with no matches is a group of one, and the group's other members stay linked to it via the shared `event_group_id` rather than being retired.
- **Dedup decision** — one evaluated pairwise comparison between two same-account extracted posts, logged to `dedup_decisions` (one row per pair): a pair-score audit log, never the mechanism that decides a merge itself. Unresolved ambiguous pairs are the manual review queue.
